# 아키텍처

## 한눈에 보기

```
브라우저 (PWA)
 ├─ Next.js App Router — 정적 앱 셸 (금융 데이터 없음)
 │    └─ src/proxy.ts — 세션 쿠키 갱신 + 비로그인 차단
 ├─ TanStack Query — 가구 데이터를 메모리에만 캐시
 ├─ lib/finance — 순수 계산 (계획 · 부채 일정 · 월 정산 · 목표 · 시뮬레이션)
 └─ supabase-js ──HTTPS──▶ Supabase (Auth + PostgREST + PostgreSQL/RLS)
```

- 서버는 Vercel의 Next.js 하나뿐이고, 별도 백엔드는 없다. 데이터 접근 권한은 **PostgreSQL RLS**가 최종 판단한다.
- 가구의 전체 데이터가 작다(수백~수천 행). 설정 테이블 전체와 최근 달의 입력 행을 한 번에 읽어 클라이언트에서 계산한다. 계획을 고치면 관련 지표가 즉시 다시 계산된다.
- 재무 계산은 전부 `src/lib/finance`의 순수 함수다. React·Supabase를 import하지 않는다.

## 기술 스택과 선정 이유

| 영역 | 선택 | 이유 |
|------|------|------|
| 프레임워크 | Next.js 16 (App Router) + React 19 + TypeScript | 단일 코드베이스로 모바일·PC 대응, Vercel 무료 배포, `proxy.ts`로 서버 수준 접근 차단 |
| 스타일 | Tailwind CSS v4 + shadcn/ui 방식 컴포넌트(Radix) | 소스가 저장소에 있어 디자인을 자유롭게 다듬을 수 있다 |
| 데이터 | Supabase (PostgreSQL + Auth + RLS) | 서버 운영 없이 인증·권한·DB를 무료 플랜으로 해결 |
| 클라이언트 캐시 | TanStack Query | 포커스 시 재조회, 변경 후 무효화. 디스크에 저장하지 않는다 |
| 차트 | Recharts | 반응형 SVG 차트, 학습 비용이 낮다 |
| 폰트 | Pretendard Variable (자체 호스팅, dynamic subset) | 한글 금융 UI 가독성, 외부 CDN 의존 없음 |
| PWA | `app/manifest.ts` + 직접 작성한 작은 서비스 워커 | 정적 자산만 캐시한다는 규칙을 코드로 명확히 통제 |
| 테스트 | Vitest (계산·DB 권한) + Playwright (E2E) | 계산은 순수 함수 단위 테스트, 권한은 실제 Supabase 로컬 스택으로 검증 |

검토 후 채택하지 않은 것:

- **서버 컴포넌트에서 데이터 조회 + Server Actions**: 화면 이동마다 서버 왕복이 생기고, 금융 데이터가 HTML에 실려 PWA 캐시 통제가 어려워진다. 두 사람이 쓰는 대화형 계산 앱에는 클라이언트 캐시가 더 단순하다.
- **Vite SPA**: 가능하지만 서버 수준 차단(proxy), 보안 헤더, 크론 라우트를 따로 구성해야 한다.
- **Serwist 등 PWA 프레임워크**: 오프라인 동기화가 요구사항이 아니므로 과하다.
- **shadcn CLI**: 개발 환경에서 레지스트리 접근이 막혀 있어 같은 구조의 컴포넌트를 직접 작성했다. `components.json`이 있으므로 이후 CLI로 컴포넌트를 추가할 수 있다.

## 데이터 흐름

### 읽기

`src/lib/data`가 가구 데이터를 한 번에 읽는다(`useHousehold()`).

- 전부 읽는 것: 가구, 구성원, 자산, 부채, 계획 항목, 목표·배정, 시나리오, 미래 이벤트, 월 목록(마감 결과 포함).
- 일부만 읽는 것: 월별 입력 행(자산·부채 스냅샷, 항목)은 **열린 달**만. 마감된 달은 `months.summary`에 동결된 결과로 충분하다(다음 달의 월초 값도 여기서 온다).
- 캐시는 메모리에만 있다. 창에 포커스가 돌아오면 다시 읽는다. `localStorage`·IndexedDB에 금융 데이터를 쓰지 않는다.

### 쓰기

- 변경은 `src/lib/data/mutations.ts`의 함수로만 한다. 성공하면 가구 쿼리를 무효화해 다시 읽는다.
- 모든 수정 가능한 행에는 `version`이 있다. 읽었던 `version`을 함께 보내고, DB 트리거가 일치하지 않으면 거부한다(`ConflictError`). 화면은 "다른 기기에서 먼저 수정했습니다"를 알리고 최신 값을 다시 읽는다.
- 두 사람이 서로 다른 행(다른 자산 잔액 등)을 고치는 것은 충돌이 아니다.
- 월 마감·재개, 가구 생성, 초대 수락, 백업 복원은 RPC(SECURITY DEFINER)로만 가능하다.
- 정산의 "한 번에 확인"은 `saveMonthInputs`가 테이블마다 한 번의 요청으로 저장한다.

### 계산

```
설정(자산·부채·계획) ─┐
직전 달 스냅샷 ───────┼─▶ lib/finance (순수 함수) ─▶ MonthPlan / MonthReport / GoalProgress / SimulationResult
이번 달 입력 ─────────┘
```

열린 달은 매번 다시 계산하고, 마감된 달은 `summary`를 그대로 보여 준다. 자세한 규칙은 [finance-rules.md](./finance-rules.md).

## 인증과 권한

1. Supabase Auth 이메일+비밀번호. 공개 회원가입은 꺼 둔다. 계정은 Supabase 대시보드에서 두 개만 만든다.
2. `src/proxy.ts`가 모든 요청에서 세션 쿠키를 갱신하고, 로그인하지 않은 사용자를 `/login`으로 보낸다(서버 수준 1차 차단).
3. 첫 사용자는 온보딩에서 가구를 만들고(`create_household`) 배우자의 이메일을 등록한다. 배우자는 그 이메일 계정으로 로그인하면 자동으로 연결된다(`claim_membership`).
4. 모든 테이블에 RLS가 켜져 있고, 정책은 `household_id = current_household_id()` 하나로 통일했다. `anon` 역할에는 테이블 권한 자체가 없다.
5. 마감된 달의 입력 행은 RLS가 쓰기를 거부한다.

## PWA와 민감 정보

- 서비스 워커는 **같은 출처의 정적 자산**(`/_next/static`, 아이콘, 폰트)만 캐시한다. Supabase 응답과 페이지 탐색 요청은 가로채지 않는다.
- 페이지 HTML은 금융 데이터가 없는 정적 셸이다. 데이터는 로그인 후 브라우저가 Supabase에서 직접 받는다.
- 로그아웃하면 세션을 지우고 전체 페이지를 새로 불러와 메모리 캐시를 버린다.
- 보안 헤더(CSP, `X-Frame-Options`, `Referrer-Policy` 등)는 `next.config.ts`에서 설정한다. CSP의 `connect-src`는 자기 출처와 Supabase URL만 허용한다.

## 주요 설계 결정

| 결정 | 이유 |
|------|------|
| 소비를 입력받지 않고 잔액 변화에서 역산한다 | "매월 5분" 목표. 내부 이체가 저절로 상쇄되어 정합성이 구조적으로 보장된다 |
| 자산마다 평가금액과 순투입액을 함께 기록한다 | 투자 평가손익과 저축 성과를 분리하기 위해 |
| 부채 상환은 계획 항목이 아니라 부채에서 파생한다 | 같은 납부액을 두 곳에 등록해 이중 차감하는 실수를 막는다 |
| 월 마감 시 결과를 JSON으로 동결한다 | 설정이나 계산 코드가 바뀌어도 과거 확정 수치가 변하지 않는다 |
| 닫힌 달은 항상 연속, 가장 최근 마감만 재개 | 과거 잔액을 고치면 다음 달 결과가 달라지므로, 순서를 강제해 불일치를 막는다 |
| 첫 달은 기준 월(잔액만) | 비교할 이전 잔액 없이 수입·소비를 추정하지 않기 위해 |
| 달이 끝난 뒤에만 마감 | 스냅샷은 월말 잔액이다. 미리 마감하면 그 뒤의 급여·지출이 다음 달 계산에 섞인다 |
| 원금 상환액·신규 차입은 가구 순액 | 대환·입주처럼 한 대출을 갚고 다른 대출을 받는 달에 저축액이 튀지 않게 |
| 보관은 계산에 영향을 주지 않는다 | 금액이 남은 자산·부채가 조용히 사라져 가짜 소비가 생기는 것을 막는다. 0을 기록해야 정리된다 |
| 구조상 정해지는 값은 제안만 하고 사용자가 확인 | "매월 5분"과 "임의로 확정하지 않는다"를 함께 지키기 위해 |
| 입력 실수는 막지 않고 알린다 | 잔액 차이로 소비를 계산하므로 자릿수 하나가 결과를 크게 바꾼다. 다만 큰 변동이 실제일 수도 있어 안내만 하고 마감은 사용자가 결정한다 |
| 계획 금액을 바꾸면 항목을 나누고 실제 값을 새 항목에 잇는다 | 지난 달의 계획을 보존하면서, 이미 확인한 수입이 두 번 집계되지 않게 한다 |
| 백업 복원은 DB 함수 하나(한 트랜잭션) | 무료 플랜에는 자동 백업이 없다. 중간에 실패해도 기존 데이터가 남아야 한다 |
| DB 컬럼명을 TypeScript에서 그대로 쓴다 | 두 사람용 서비스에 매핑 계층은 과하다 |
| 금액은 `bigint` 원 단위 | 부동소수점 오차 원천 차단 |
| 실시간 구독 대신 포커스 재조회 + 낙관적 잠금 | 동시 수정으로 인한 데이터 손실은 막으면서 구성 요소를 줄인다 |
