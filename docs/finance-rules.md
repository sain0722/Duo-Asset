# 재무 계산 규칙

DuoAsset의 모든 숫자는 이 문서의 정의를 따른다. 계산 코드는 `src/lib/finance/`에 순수 함수로 있고, UI·DB에 의존하지 않는다. 규칙을 바꾸면 이 문서, 코드, 테스트를 함께 고친다.

## 1. 기본 원칙

| # | 원칙 | 구현 방식 |
|---|------|-----------|
| 1 | 금액은 KRW 원 단위 정수 | DB `bigint`, JS 정수 `number`. 비율 계산은 정해진 지점에서 `Math.round` 한 번만 한다. |
| 2 | 매일 가계부를 쓰지 않는다 | 월말 잔액과 수입만 입력하면 소비는 **잔액 변화에서 역산**한다. |
| 3 | 내부 이동은 소비가 아니다 | 계좌 간 이체, 공용통장 납입, 적금 납입은 자산의 위치만 바꾼다. 가구 합계에서는 저절로 상쇄된다. |
| 4 | 예정과 실제를 섞지 않는다 | 계획(`plan_items`, 부채 일정)과 실제(`*_snapshots`, `month_entries`)는 다른 테이블이다. |
| 5 | 미확인 ≠ 0원 | 실제 값은 "행이 없음 = 미확인", "0 = 실제 0원"으로 구분한다. |
| 6 | 마감한 달은 바뀌지 않는다 | 마감 시 결과(`MonthReport`)를 `months.summary`에 동결하고, 입력 행은 DB가 수정을 막는다. |
| 7 | 중복 집계 금지 | 부채 상환액은 `liabilities`에서만 파생시키고 계획 항목으로 따로 두지 않는다. 자산·부채는 각각 한 테이블에서만 집계한다. |

## 2. 주머니(pocket)

돈이 머무는 단위. 구성원 개인 주머니(구성원마다 하나)와 **공동 주머니**(공용통장과 공동 명의 자산)가 있다.

- 자산은 `owner_member_id`(null = 공동)로, 부채는 `payer_member_id`(null = 공용통장에서 납부)로 주머니가 정해진다. 주머니는 명의가 아니라 **돈의 출처** 기준이다: 공용통장 돈으로 붓는 적금은 누구 명의든 공동 자산으로 등록한다.
- 주머니 사이의 이동만 따로 기록한다(공용통장 납입, 기타 이체). **같은 주머니 안의 이동은 입력할 필요가 없다.**

## 3. 자산의 두 숫자: 평가금액과 순투입액

모든 자산 스냅샷은 `value`(월말 평가금액)와 `principal`(누적 순투입액)을 가진다.

- **순투입액** = 지금까지 넣은 돈 − 뺀 돈. 세법상 취득원가가 아니다. 주식을 전부 팔아 1,200만 원을 인출했다면 순투입액은 1,200만 원 줄어든다(음수가 될 수 있다).
- 현금성 자산(`cash`, `deposit`, `savings`)과 `lease_deposit`, `presale`은 `principal = value`로 저장한다(잔액 하나만 입력).
- 투자자산(`investment`, `pension`)과 `real_estate`, `vehicle`, `other`는 둘을 따로 관리한다.

한 달 동안 자산 a에 대해:

```
순투입(contributed) = principal_말 − principal_초
평가손익(gain)      = (value_말 − value_초) − 순투입
```

월초 값은 직전 달의 정산 결과(마감했다면 동결된 결과)에 있는 월말 값이다. 직전 달에 그 자산이 없었으면:

- 스냅샷에 `opening_value / opening_principal`이 있으면 그 값(전부터 갖고 있던 자산을 뒤늦게 등록한 경우). 이 금액은 **기초 조정**으로 분리되어 수입·저축 계산에 영향을 주지 않는다.
- 없으면 0(이번 달에 새로 생긴 자산).

이번 달 스냅샷이 없으면(미확인) 월초 값이 그대로 유지된 것으로 **가정**하고 `confirmed = false`로 표시한다. 결과는 `complete = false`가 된다.

**보관(`is_active = false`)은 계산에 영향을 주지 않는다.** 금액이 남아 있는 자산·부채는 보관해도 계속 집계되고 계속 확인을 요구한다. 해지·매각·완납으로 정리하려면 그 달에 0을 기록한다. 평가금액과 다른 값에 팔았다면 순투입액을 받은 금액만큼 줄인다 — 차액은 소비가 아니라 평가 변동이 된다. 금액이 0이 된 뒤 보관한 자산·부채는 다음 달부터 집계에서 빠진다.

부채도 같다. `balance`가 월말 남은 원금이고, `순상환 = balance_초 − balance_말`(음수면 신규 차입)이다.

## 4. 지표 정의

| 지표 | 정의 |
|------|------|
| 총자산 | 자산 평가금액의 합 |
| 총부채 | 부채 남은 원금의 합 |
| 순자산 | 총자산 − 총부채 |
| 가용자산 | 유동성이 `liquid`(즉시 사용 가능)인 자산의 합 |
| 금융자산 | `cash`, `deposit`, `savings`, `investment`, `pension` 합 |
| 수입 | 실제로 받은 **현금** 수입. 비현금 복지(식비 카드 등)는 포함하지 않는다. |
| 소비지출 | 수입 − Σ자산 순투입 − Σ부채 순상환. 이자, 용돈, 생활비 등 가구 밖으로 나간 모든 돈. |
| 원금 상환액 | 부채 잔액 **합계**가 줄어든 만큼 (늘었으면 0) |
| 신규 차입 | 부채 잔액 **합계**가 늘어난 만큼 (줄었으면 0) |
| 저축액 | 수입 − 소비지출 − 원금 상환액 = Σ자산 순투입 − 신규 차입 |
| 저축률 | 저축액 ÷ 수입 (%, 소수 1자리). 수입이 0이면 표시하지 않는다. |
| 투자 평가손익 | `investment`, `pension` 자산의 평가손익 합 |
| 기타 평가 변동 | 그 외 자산(부동산, 자동차 등)의 평가손익 합 |
| 기초 조정 | 뒤늦게 등록한 기존 자산 − 기존 부채 |

항상 성립하는 항등식(테스트로 검증한다):

```
순자산 변화 = 저축액 + 원금 상환액 + 투자 평가손익 + 기타 평가 변동 + 기초 조정
수입       = 소비지출 + 저축액 + 원금 상환액
저축액     = Σ자산 순투입 − 신규 차입
```

### 왜 이렇게 정의하는가

- **공용통장 납입·계좌 이체·적금 납입**: 한 자산의 순투입이 줄고 다른 자산이 같은 만큼 늘어 합계가 0이다. 소비도 저축도 변하지 않는다.
- **대출 원금 상환**: 현금 순투입이 줄고 부채 순상환이 같은 만큼 늘어난다. 소비는 그대로, 순자산도 그대로다. 저축액은 그만큼 줄고 원금 상환액이 그만큼 늘어난다 → "원금 상환으로 인한 순자산 개선"과 "저축으로 인한 자산 증가"가 분리된다.
- **이자·부모님 용돈(원금 미상환형 차용금 지급)**: 현금만 줄고 상쇄되는 항목이 없으므로 소비지출이 된다. 부채 잔액은 그대로다.
- **투자 평가손익**: 순투입 없이 평가금액만 변하므로 저축액에 섞이지 않는다.
- **자동차 감가**: 평가금액만 줄어 "기타 평가 변동"이 된다.
- **대출로 자산 취득**: 자산 순투입이 늘지만 같은 금액의 신규 차입을 빼므로 저축액은 0이다. 빌린 돈을 써 버리면 그만큼 소비지출이 늘고 저축액은 음수가 된다.
- **대환·입주**: 한 대출을 갚고 다른 대출을 받는 달에는 원금 상환액과 신규 차입을 가구 **순액**으로 본다. 부채별로 따로 더하면 저축액이 억 단위로 튀기 때문이다. 부채별 변화는 부채 줄에 그대로 남는다.

### 주의할 점

- 예금 이자나 만기 이자처럼 기록하지 않은 수입이 있으면 그만큼 소비지출이 작게 계산된다. 필요하면 "기타 수입"으로 추가한다. 소비지출이 음수가 되면 수입 누락 가능성을 경고한다.
- 퇴직연금에 회사가 넣어 주는 금액은 급여통장을 거치지 않는다. 순투입으로 올리지 않으면 평가손익으로 잡힌다. 저축으로 보고 싶다면 순투입액을 올리면서 **같은 금액을 기타 수입으로 함께 기록**한다(수입 없이 순투입만 올리면 그만큼 소비지출이 작게 계산된다).

## 5. 주머니별 소비

```
주머니 소비 = 주머니 수입 + 들어온 이동 − 나간 이동 − 주머니 자산 순투입 − 주머니 부채 순상환
```

- 구성원이 공용통장에 넣은 실제 금액(`contribution`)은 개인 주머니의 "나간 이동", 공동 주머니의 "들어온 이동"이다.
- 그 밖의 주머니 간 이동은 `transfer` 항목으로 기록한다.
- 주머니 소비의 합은 가구 소비지출과 같다.
- 주머니 소비 중 사용자가 확인한 지출(`expense` 항목 + 확인된 이자)을 뺀 나머지는 **미분류 지출**이다. 개인 주머니에서는 사실상 개인 생활비, 공동 주머니에서는 공동생활비다. 미분류 지출을 임의의 항목으로 확정하지 않는다.
- 주머니 소비나 미분류 지출이 음수면 경고한다. 빠진 수입, 기록하지 않은 주머니 간 이동, 다른 주머니에서 낸 지출이 섞인 경우다.
- 저축 계획 항목의 대상 자산은 같은 주머니의 자산만 고를 수 있다. 다른 주머니의 자산으로 돈을 보냈다면 이동(`transfer`)으로 기록한다.
- 자동차 할부금이 본인 통장에서 나가면 본인 주머니의 부채 순상환으로만 잡힌다. 공동 소비에는 들어가지 않는다.

## 6. 계획(월급 배분)

특정 월의 계획은 그 달에 유효한 `plan_items`와 부채 일정에서 계산한다.

항목이 그 달에 유효한 조건: `is_active` 이고, `start_month ≤ 월 ≤ end_month`(null은 제한 없음)이고, `months_of_year`가 null이거나 그 달을 포함한다.

구성원별:

```
개인 사용 가능 금액 = 현금 수입 − 개인 고정지출 − 개인 부채 상환(원금+이자) − 공용통장 납입 − 개인 저축
```

공동:

```
공동저축 = 구성원 납입 합 + 공동 수입 − 공동지출 − 공동 부채 상환(원금+이자)
```

공용통장에서 다른 공동 자산(예: 공동 적금)으로 옮기기로 한 금액은 공동저축의 **일부**이지 추가분이 아니다.

가구 합계:

```
계획 소비     = Σ개인 고정지출 + Σ이자 + Σ개인 사용 가능 금액(음수는 0) + 공동지출
계획 원금상환 = Σ부채 원금
계획 저축     = 수입 − 계획 소비 − 계획 원금상환
```

개인 사용 가능 금액은 **쓰는 돈으로 본다**(보수적). 쓰고 남기면 실제 저축이 계획을 넘는다. 더 저축할 계획이면 저축 항목으로 등록한다. 사용 가능 금액이 음수면 수입보다 많이 배분한 것이므로 경고한다.

저축 목표 달성률 = 실제 저축액 ÷ 계획 저축액.

## 7. 부채 일정

`liabilities`의 종류별로 n번째 납부(1부터, `start_month`가 1번째)의 예정액을 계산한다. 월 이율 r = 연 이율 ÷ 12. 이자는 `round(남은 원금 × r)`.

| 종류 | 원금 | 이자 |
|------|------|------|
| `installment` 무이자 할부 | `monthly_payment`(없으면 `round(최초 원금 ÷ 기간)`), 마지막 회차는 남은 원금 전부 | 0 |
| `equal_principal` 원금균등 | `round(최초 원금 ÷ 기간)`, 마지막 회차는 남은 원금 전부 | 남은 원금 × r |
| `amortized` 원리금균등 | 월 납부액 − 이자, 마지막 회차는 남은 원금 전부. 월 납부액은 **남은 원금을 남은 회차에** 나눈 금액: `round(B·r·(1+r)^k ÷ ((1+r)^k − 1))` (B = 월초 잔액, k = 남은 회차), r = 0이면 `round(B ÷ k)` | 남은 원금 × r |
| `bullet` 만기일시 | 마지막 회차에 남은 원금 전부, 그 전에는 0 | 남은 원금 × r |
| `interest_only` 원금 유지 차용금 | 0 | `monthly_payment` (이자·용돈 등 비원금 지급). 없으면 남은 원금 × r |

- 원리금균등은 은행과 같은 방식으로 다룬다: 금리를 바꾸거나 중도상환을 하면 만기는 그대로이고 월 납부액이 다시 계산된다.
- 이자가 있는 대출(원리금균등·원금균등·만기일시)은 기간과 첫 납부 월이 있어야 한다. 무이자 할부는 월 납부액이나 기간 중 하나가 있어야 한다.
- `start_month` 이전이거나 남은 원금이 0이면 예정액은 0이다. 원금이 없는 정기 지급은 부채가 아니라 고정지출 항목으로 등록한다(부채의 최초 원금은 0보다 커야 한다).
- 예정액은 **그 달의 월초 실제 잔액**을 기준으로 계산한다(중도상환을 했다면 이후 이자가 줄어든다).
- 실제 상환은 스냅샷의 잔액 변화로, 실제 이자는 `interest_paid`로 기록한다. 예정과 실제는 나란히 보여 준다.
- 부채가 끝나면 그 달부터 `월 납부액`만큼 매월 여유 자금이 늘어난다.

## 8. 월 정산과 마감

1. 열린 달은 현재 설정으로 계산한 계획과 입력된 실제 값으로 **매번 다시 계산**한다. 미확인 항목이 남아 있는 동안(`complete = false`) 수입·소비·저축 같은 흐름 지표는 잠정값일 뿐이다 — 미확인 수입은 계획 금액, 미확인 잔액은 전월 값으로 가정하기 때문에 "수입 전액을 썼다"처럼 보일 수 있다. 화면은 이런 달의 흐름 지표를 결과로 보여 주지 않고 **정산 전**으로 표시한다. 홈의 실제 저축액·저축 목표 달성률은 마지막으로 마감한 달 기준이다.
2. 마감하려면 금액이 남아 있는 모든 자산·부채의 스냅샷, 계획된 수입·납입의 실제 금액이 확인되어야 한다(`complete = true`). 데이터 계층과 DB 함수도 미완료 결과의 마감을 거부한다. "전월과 동일", "계획대로"로 한 번에 확인할 수 있지만 사용자가 명시적으로 눌러야 한다.
3. 마감하면 `MonthReport`(그 달의 계획 줄 포함)가 `months.summary`에 저장되고 다음 달이 열린다. 이후 화면은 저장된 결과만 보여 준다.
4. 닫힌 달은 항상 앞쪽에 연속으로 있다. 가장 최근에 마감한 달만 다시 열 수 있고, 가장 이른 열린 달만 마감할 수 있다.
5. 다시 연 달의 계획은 마감 당시 동결된 계획 줄을 그대로 쓴다. 현재 설정으로 바뀌지 않는다.
6. 첫 달은 **기준 월**이다. 비교할 이전 잔액이 없으므로 잔액 지표만 집계하고 수입·소비·저축은 계산하지 않는다.
7. **스냅샷은 그 달 말일의 잔액이고, 달이 끝난 뒤(Asia/Seoul)에만 마감할 수 있다.** 달이 끝나기 전에 마감하면 그 뒤에 들어온 급여·지출이 다음 달 잔액 변화에 섞여 소비가 작게, 저축이 크게 계산된다. 데이터 계층과 DB 함수가 모두 막는다. 그래서 서비스를 시작할 때는 **지난달을 기준 월**로 잡고 지난달 말 잔액을 입력하는 것이 가장 빠르다(이번 달 정산부터 분석이 나온다).
8. 값이 구조상 정해지는 항목(예금·적금·보증금·분양 납부금의 "전월 + 저축 계획", 부채의 "예정대로", 수입·납입의 "계획대로")은 화면이 목록으로 제안하고 사용자가 한 번에 확인할 수 있다(`suggestInputs`). 입출금 통장과 투자자산은 직접 확인해야 한다. 제안은 사용자가 누르기 전에는 저장되지 않는다.

## 9. 목표

- 목표는 자산이 아니라 자산의 **사용 목적**이다. 목표를 만들어도 총자산은 변하지 않는다.
- 현재 확보 금액의 기준(`basis`): 연결한 자산의 배정액 합 / 직접 입력 / 순자산 / 가용자산 / 금융자산.
- 한 자산을 여러 목표에 연결할 수 있다. 목표를 정렬 순서대로 돌면서 자산의 남은 평가금액 안에서만 배정한다. `amount = null`("남은 전부")도 그 목표에 필요한 만큼만 가져가므로 다음 목표가 같은 자산의 나머지를 쓸 수 있다. 요청액을 채우지 못하면 부족분(`shortfall`)으로 표시한다. → 배정액 합계는 자산 평가금액을 넘지 않는다.
- 가용자산·금융자산 기준 목표의 현재 금액은 다른 목표에 이미 배정된 금액을 뺀 값이다(같은 돈을 두 번 세지 않는다). 순자산 기준 목표는 전체 재산을 보는 목표라 배정과 무관하다.
- 목표 배정 후 여유 가용자산 = 가용자산 − 가용자산에 걸린 배정액 합.
- 예상 달성 시점: 순자산·금융자산 기준 목표는 기본 시나리오 시뮬레이션에서 처음 목표를 넘는 달. 그 밖의 목표는 월 적립 계획이 있을 때 `남은 금액 ÷ 월 적립액`(올림)개월 뒤. 가용자산 기준 목표는 시뮬레이션을 쓰지 않는다(시뮬레이션은 유동성별 잔액을 추적하지 않는다).

## 10. 미래 시뮬레이션

시뮬레이션은 **가정**이다. 실제 기록을 읽기만 하고 바꾸지 않는다.

출발점: 가장 최근 달의 정산이 끝났으면 그 달 말 잔액에서 다음 달부터, 아직 미확인 항목이 있으면 그 달부터 다시 굴린다(정산 전인 달의 저축과 상환을 건너뛰지 않는다). 정산 전인 달에서 아직 확인하지 않은 항목은 월초 값에서, 이미 확인한 부채는 "이번 달 예정 원금을 갚으면 확인한 잔액이 되는" 값에서, 이번 달에 처음 생긴 자산은 확인한 값에서 출발한다. 기존 현금으로 새 자산을 샀다면 정산을 마칠 때까지 그 금액이 잠시 이중으로 잡힐 수 있고, 원리금균등 대출을 중도상환한 달에는 출발 잔액이 확인한 잔액과 조금(잔액의 0.3% 이내) 다를 수 있다. 둘 다 정산을 마치면 사라지는 근사다. 미래 달의 계획을 볼 때도 같은 출발점에서 부채 잔액을 예정대로 굴린다.

상태: 현금성 자산, 투자자산, 비금융 자산(부동산·분양 납부금·기타), 부채 목록. 매월 다음 순서로 계산한다:

1. **수익**: 월초 잔액에 붙인다. 투자자산 × 월 수익률, 현금성 자산 × 월 이자율(음수인 현금에는 붙이지 않는다), 부동산 × 월 상승률. 월 이율 = (1 + 연이율)^(1/12) − 1. 결과는 원 단위로 반올림한다.
2. **수입** = 그 달에 유효한 수입 항목 합. 급여와 상여금은 매년 1월에 `연봉 인상률`만큼 오른다(시뮬레이션 시작 연도 기준. 계획 항목의 금액은 모두 현재 가치로 본다). 이벤트의 소득 증감을 더하고, 휴직 기간에는 그 구성원의 수입을 휴직 중 수령액으로 대체한다. 주머니별 수입은 0 미만으로 내려가지 않는다.
3. **소비** = (그 달에 유효한 지출 항목 합 + 시작 시점의 개인 사용 가능 금액) × 생활비 증가율(매년 1월) + 이벤트 지출 증감 − 월 저축 조정액. 0 미만으로 내려가지 않는다. 개인 사용 가능 금액은 매월 반복되는 항목만으로 계산한 값을 계속 쓴다. 그래서 수입이 늘거나, 상여금을 받거나, 할부가 끝나 생긴 여유는 저축으로 쌓인다.
4. **이벤트**: 일회성 수입·지출, 자산 취득(현금 ↔ 비금융 자산), 대출 실행(현금 또는 자산이 늘고 부채가 생긴다. 첫 납부는 실행한 다음 달), 주택 입주(분양 납부금 → 부동산 전환, 잔금, 대출, 보증금 반환, 주거비 변화), 주택 매도(보유 부동산 전체가 매도 대금만큼의 현금이 되고, 지정한 대출을 그 자리에서 갚는다 — 갈아타기는 주택 매도와 주택 입주를 함께 등록한다), 대출 상환 완료(남은 원금을 현금으로 한 번에 갚는다).
5. **부채 상환**: 7절의 일정대로 원금·이자를 낸다. 이자는 소비에 더한다. 끝나면 마일스톤으로 기록하고, 평소 월 납부액(만기일시상환은 매월 내던 이자)을 "풀리는 월 여유 자금"으로 표시한다. 보관한 부채도 원금이 남아 있으면 계속 갚는다.
6. **현금 흐름** = 수입 − 소비 − 원금상환 → 현금성 자산에 더한다. 그다음 `월 투자액`만큼 현금에서 투자자산으로 옮긴다(기본값: 투자·연금 자산에 연결된 저축 계획 항목의 합).
7. 현금성 자산이 음수가 되면 **자금 부족** 마일스톤을 남긴다(음수 그대로 계속 진행).

이벤트의 시점: 시작 월보다 앞선 **일회성** 효과(일회 지출, 자산 취득, 대출 실행)는 이미 현재 잔액에 반영된 것으로 보고 버린다. **기간** 효과(소득·지출 증감, 휴직)는 끝나지 않았으면 계속 적용한다. 이벤트가 현실이 되어 계획 항목(급여, 지출 등)에 반영했다면 이중으로 잡히지 않도록 이벤트를 지우거나 끈다.

시나리오는 가정값과 적용할 이벤트의 집합이다. 이벤트는 공통(모든 시나리오)이거나 특정 시나리오 전용이고, 시나리오별로 공통 이벤트를 끌 수 있다.
