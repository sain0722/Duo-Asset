# 제한사항과 향후 계획

## 현재 제한사항

### 계산

- **기록하지 않은 수입은 소비를 줄여 보이게 한다.** 예금 이자, 환급, 적금 만기 이자처럼 통장에 들어왔지만 수입으로 적지 않은 돈이 있으면 그만큼 소비지출이 작게 계산된다. 소비가 음수가 되면 경고하지만, 작은 금액은 알아채기 어렵다.
- **주머니별 소비는 주머니 간 이동을 기록한 만큼만 정확하다.** 가구 합계는 항상 맞지만, 공용통장에서 개인 계좌로 보낸 돈을 이동으로 적지 않으면 공동 소비와 개인 소비가 그만큼 서로 어긋난다.
- **정산을 건너뛴 달은 한 달씩 순서대로 정산해야 한다.** 여러 달을 한 번에 합산 정산하는 기능은 없다. 건너뛴 달의 잔액을 모르면 "변동 없음"으로 확인하고 넘어갈 수 있지만, 그 달의 소비는 다음 달에 몰려 잡힌다.
- **첫 달(기준 월)은 잔액만 기록한다.** 수입·소비 분석은 다음 달 정산부터 나온다.
- **변동금리 대출은 금리를 직접 고쳐야 한다.** 금리를 바꾸면 남은 원금을 남은 기간에 맞춰 다시 계산한다. 거치 기간, 체증식 상환 등은 지원하지 않는다(실제 잔액을 매달 확인하므로 실적은 정확하다).
- **시뮬레이션은 단순화한 가정이다.** 세금, 물가 연동, 자산별 수익률 차이, 유동성별 잔액은 다루지 않는다. 가용자산 기준 목표의 예상 달성 시점은 월 적립 계획이 있을 때만 계산한다.
- **주식은 계좌 단위로만 관리한다.** 종목별 수량·시세는 다루지 않는다.

### 서비스

- 온라인 전용이다. 오프라인에서는 화면 틀만 열리고 데이터는 보이지 않는다.
- 두 사람이 같은 화면을 동시에 볼 때 상대의 입력은 저장하거나 창으로 돌아올 때 반영된다(실시간 푸시 없음). 같은 항목을 동시에 고치면 나중 쪽에 충돌을 알린다.
- 계정 발급·비밀번호 분실 처리는 Supabase 대시보드에서 한다.
- Supabase 무료 플랜에는 자동 백업이 없다. 설정 화면의 백업 내보내기를 주기적으로 실행해야 한다.
- 가구 구성원은 두 명으로 고정이다.

## 향후 계획

필요가 확인되면 진행한다. 아직 필요하지 않은 구조를 미리 만들지 않는다.

| 우선순위 | 내용 |
|----------|------|
| 높음 | 정산 알림: 월말·월초에 정산을 알려 주는 푸시 또는 이메일 |
| 높음 | 자동 백업: 정해진 주기로 백업 파일을 만들어 보관(예: Vercel Cron + 저장소) |
| 중간 | 실시간 동기화: Supabase Realtime 구독으로 배우자의 입력을 바로 반영 |
| 중간 | 여러 달 합산 정산: 건너뛴 달을 한 번에 처리 |
| 중간 | 연간 리포트: 연 단위 수입·소비·저축·순자산 요약과 전년 대비 |
| 중간 | 지출 분류 통계: 확인한 지출 항목의 월별 추이 |
| 낮음 | 목표별 시뮬레이션: 목표 달성 시점을 시나리오별로 비교 |
| 낮음 | 대출 상환 방식 확장: 거치 기간, 체증식, 변동금리 일정 |
| 낮음 | CSV 가져오기: 다른 가계부에서 과거 월별 잔액을 불러오기 |

## 만들지 않기로 한 것

은행 실시간 연동, 카드 승인내역 수집, 마이데이터, 영수증 OCR, 주식 실시간 시세, AI 소비 분석, 커뮤니티, 광고, 구독 결제, 불특정 다수용 기능, 네이티브 앱. 필요성이 확인되기 전에는 추가하지 않는다.
